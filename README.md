# VLESS через Timeweb CDN

Отдельный установщик VLESS + XHTTP + TLS и веб-панель выдачи ключей.
Основан на [vless-server-kit](https://github.com/grislytoe/vless-server-kit) и
профиле Timeweb из [web-panel-proxy](https://github.com/POLESNIESOVETI12/web-panel-proxy).
Инструкция повторяет последовательность из [видео](https://youtu.be/QQ1WVviBe2A),
но использует нашу панель и Nginx. Чужие установочные скрипты не выполняются.

```text
Happ / Xray → HTTPS, домен CDN → Timeweb CDN
                                  ↓ HTTPS, домен источника
                           Nginx на VPS:443
                                  ↓ HTTP, только loopback
                           Xray:26869 → интернет
```

Это новый проект для чистого VPS. Он не обновляет установленный REALITY-комплект
и не переносит автоматически его клиентов. На сервере нельзя смешивать эти установщики.

## Порядок действий

1. [Заказать нужные услуги](#services) — VPS, домен и CDN.
2. [Создать DNS-запись источника](#dns-origin).
3. [Подключиться к VPS по SSH](#ssh).
4. [Скачать и установить проект](#install).
5. [Создать ресурс CDN и настроить его](#cdn).
6. [Создать CNAME домена раздачи](#dns-cdn) и выпустить сертификат CDN.
7. [Проверить туннель и подключить Happ](#connect).

Все команды с `bash`, `apt-get`, `python3` выполняются **на VPS после подключения по SSH**.
Команды из блока PowerShell выполняются **на вашем Windows-ПК**.

<a id="services"></a>

## Что именно заказывать в Timeweb

Для этой схемы нужны **три отдельные составляющие**:

| Что | Какую услугу выбрать | Для чего |
|---|---|---|
| Сервер | **Timeweb Cloud → Облачные серверы / VPS / VDS**, обычный виртуальный сервер с Ubuntu 24.04 | На нём установятся Xray и наша админка |
| Домен | **Регистрация домена** у Timeweb или другого регистратора; если домен уже есть, новый покупать не нужно | Из одного домена создадим два поддомена: `vpn` и `cdn` |
| CDN | **Timeweb Cloud → Сети → CDN → Добавить**, источник типа **«Домен»** | Это отдельный посредник между клиентом и вашим VPS |

**Обычный виртуальный хостинг для сайтов для этого установщика не подходит**:
нужен сервер с root/SSH и systemd. S3-бакет, выделенный физический сервер,
управляемая база данных и платная панель управления для этой схемы не нужны.
Админка уже входит в проект. В этом варианте VPS находится в Timeweb Cloud;
технически источником CDN может быть и VPS другого провайдера.

### Как создать VPS

В панели облачных серверов создайте новый сервер со следующими параметрами:

| Поле | Что выбрать |
|---|---|
| Образ / ОС | **Ubuntu 24.04**, чистый образ без готовой панели |
| Тип | Обычный облачный сервер с доступом root по SSH |
| Процессор | Поддерживается x86_64 или ARM64 |
| Публичная сеть | **Один публичный IPv4**, назначенный серверу |
| Доступ | SSH-ключ или пароль root, который вы сохраните у себя |
| Firewall провайдера | Разрешить входящие TCP **80**, **443** и ваш SSH-порт (обычно **22**) |

Скрипт не навязывает тариф по CPU/RAM: выбирайте по нагрузке и числу пользователей.
Ограничение канала и включённый трафик проверяйте в карточке тарифа.
Дополнительный IPv4 не требуется. Не выбирайте сервер только с приватной сетью.

После создания запишите **реальный публичный IPv4** из карточки сервера.
Далее в инструкции вместо него используется учебный адрес `203.0.113.10`.
Этот адрес нужно заменить: подключаться к нему как к настоящему VPS нельзя.

### Нужны ли два домена

Нет. Достаточно одного зарегистрированного домена, например `example.com`.
В его DNS создаются два поддомена:

| Имя | Назначение | Куда должно вести |
|---|---|---|
| `vpn.example.com` | Источник CDN и вход в админку | Непосредственно на IP вашего VPS |
| `cdn.example.com` | Адрес подключения Happ | На технический домен ресурса Timeweb CDN |
| `example.com` и `www.example.com` | Основной сайт, если он есть | Для VPN менять не требуется |

Весь дальнейший пример использует эти имена. Если ваш домен другой, заменяйте
`example.com` **во всех полях и командах**, сохраняя различие между `vpn` и `cdn`.

<a id="dns-origin"></a>

## DNS до установки: A-запись для VPS

Редактировать записи нужно **у провайдера, чьи NS-серверы обслуживают ваш домен**.
Покупка домена у Timeweb сама по себе не означает, что DNS сейчас управляется там.
Если DNS размещён у другого провайдера, создавайте записи в его панели.
Менять NS ради этой схемы необязательно.

Откройте DNS-зону вашего домена и добавьте запись:

| Поле в DNS-панели | Значение |
|---|---|
| Тип записи | **A** |
| Имя / поддомен / хост | **`vpn`** |
| Значение / IPv4 | **Реальный публичный IPv4 VPS**; в примере `203.0.113.10` |
| TTL | Можно оставить значение по умолчанию |

Некоторые панели требуют полное имя `vpn.example.com` вместо короткого `vpn`.
Ориентируйтесь на предпросмотр: итоговое имя должно быть ровно `vpn.example.com`,
а не `vpn.example.com.example.com`.

На этом этапе итоговая запись такая:

```text
vpn.example.com.    A    203.0.113.10
```

Для `vpn` оставьте одну A-запись — только входной IP VPS. Не создавайте для него
CNAME на CDN. Если у вашего DNS-провайдера есть проксирование, запись `vpn` должна
работать в режиме **только DNS / DNS only**. Неподготовленную AAAA-запись `vpn` удалите.
Существующие записи основного сайта и почты изменять не нужно.

Проверьте результат на Windows в PowerShell:

```powershell
Resolve-DnsName vpn.example.com -Type A
```

В результате должен быть ваш IP VPS. Пока возвращается другой адрес или домен
не находится, установку не начинайте. Обновление DNS не происходит мгновенно;
важен правильный ответ DNS, а не фиксированное число минут ожидания.
Поддомен `cdn` настроим после создания CDN-ресурса, когда узнаем его техническое имя.

<a id="ssh"></a>

## Как зайти на сервер с Windows

Откройте PowerShell и выполните, подставив IP вашего VPS:

```powershell
ssh root@203.0.113.10
```

Если используется другой SSH-порт:

```powershell
ssh -p 2222 root@203.0.113.10
```

При первом подключении SSH покажет отпечаток ключа сервера. Сверьте его с данными
провайдера или через консоль сервера, затем подтвердите подключение. Введите пароль
root, если подключаетесь по паролю: символы при вводе не отображаются.
Не путайте пароль SSH с паролем админки — пароль админки вы зададите при установке.

После входа команды выполняются уже на Linux-сервере. Проверить ОС можно так:

```bash
cat /etc/os-release
ip -o -4 addr show scope global
```

Если вошли под пользователем с sudo, сначала выполните `sudo -i`.

## 1. Что подготовить

- Чистый VPS: Ubuntu 24.04 (как в видео), Ubuntu 22.04, Debian 12/13; x86_64 или ARM64, systemd.
- Один публичный IPv4, назначенный интерфейсу VPS. Второй IP необязателен.
- Домен источника, например `vpn.example.com`: DNS A указывает прямо на IPv4 VPS.
- Отдельный домен раздачи, например `cdn.example.com`. Его CNAME настроим после создания CDN.
- Доступ root по SSH, открытые TCP 80 и 443. Сохраните доступ к своему SSH-порту.
- Аккаунт Timeweb Cloud и средства на сервер/CDN/домен. Цены и лимиты проверяйте в панели провайдера.

IPv6 установщик не обслуживает: не добавляйте AAAA источника, ведущую на неподготовленный IPv6.
Домен источника нельзя направлять на CDN: он нужен для HTTPS источника и админки.
При регистрации домена указывайте достоверные данные владельца согласно требованиям регистратора.

<a id="install"></a>

## 2. Скачать и установить

В SSH-сессии root установите инструменты загрузки:

```bash
apt-get update
apt-get install -y ca-certificates curl python3 iproute2 util-linux tar
```

Скачайте архив выбранного полного commit SHA из этого репозитория. SHA можно скопировать
со страницы [коммитов](https://github.com/grislytoe/vless-timeweb-cdn/commits/main).
Ниже уже указан проверенный SHA. Новый снимок распаковывайте в новую папку:

```bash
REVISION=3646f3bddf07d419481e4d19fe9281769d97ef97
curl --proto '=https' --tlsv1.2 -fL --retry 3 \
  "https://codeload.github.com/grislytoe/vless-timeweb-cdn/tar.gz/$REVISION" -o timeweb-kit.tar.gz
mkdir "timeweb-kit-$REVISION"
tar -xzf timeweb-kit.tar.gz --strip-components=1 -C "timeweb-kit-$REVISION"
cd "timeweb-kit-$REVISION"
sha256sum --strict -c SHA256SUMS
bash start.sh
```

В блоке указан снимок, прошедший проверки Linux x86_64 и ARM64.
Для другой версии замените значение `REVISION` полным SHA выбранного коммита.
Не продолжайте установку, если проверка `SHA256SUMS` завершилась ошибкой.

Manifest проверяет целостность файлов внутри скачанного снимка, но не является
независимой подписью архива. Для проверки заранее известного SHA256 архива есть
`bootstrap.sh`: он требует `VLESS_KIT_REVISION` и `VLESS_KIT_ARCHIVE_SHA256`.

Установщик спросит домен источника, IPv4 VPS, домен CDN, логин и пароль панели.
Пароль вводится скрыто; не передавайте его в командной строке или чате.
Пример ответов:

| Вопрос установщика | Что вводить |
|---|---|
| `Origin domain` | `vpn.example.com` — без `https://`, порта и пути |
| `VPS public IPv4` | Реальный IPv4 вашего сервера |
| `CDN domain` | `cdn.example.com` — без `https://`, порта и пути |
| `Panel login` | Придуманный логин: 3–40 латинских букв, цифр, `_` или `-` |
| `Panel password` | Придуманный пароль длиной 16–256 символов |
| `Repeat password` | Тот же пароль ещё раз |

Домен CDN на этом этапе может ещё не разрешаться в DNS. Для первого этапа обязателен
правильный A домена источника. Первый ключ будет создан заранее, но использовать
его через CDN можно после завершения следующих шагов.

Можно заранее передать несекретные параметры:

```bash
bash install.sh --check \
  --domain=vpn.example.com --inbound=203.0.113.10 --cdn-domain=cdn.example.com
bash start.sh \
  --domain=vpn.example.com --inbound=203.0.113.10 --cdn-domain=cdn.example.com
```

`203.0.113.10` — пример, замените его реальным адресом. По умолчанию выход в интернет
использует тот же IP. Для дополнительного назначенного IPv4 есть `--outbound=IP`.
`--check` не устанавливает пакеты и не изменяет службы; проверяет DNS, адреса и доступность выхода.

При установке запрашивается сертификат Let's Encrypt (с принятием условий сервиса),
создаются службы Xray, Nginx, локальный менеджер и непривилегированная веб-панель.
Продление сертификата использует HTTP-01: TCP 80 должен оставаться доступным.
Скрипт не меняет firewall, MTU и глобальные настройки TCP.

В конце будут адрес панели и расположение первого ключа. Установка проверяет туннель
**напрямую через источник**; это ещё не проверка Timeweb CDN.

<a id="cdn"></a>

## 3. Настроить Timeweb CDN

Создавайте **новый CDN-ресурс**, а не второй VPS и не S3-бакет.
Создание и обслуживание CDN оплачиваются отдельно от сервера и домена.
Точные цены, включённый трафик и стоимость превышения смотрите перед заказом
в панели Timeweb: суммы из видео могут измениться.

### Какие значения вводить в CDN

| Настройка | Значение для нашего примера |
|---|---|
| Тип источника | **Домен** |
| Домен источника | **`vpn.example.com`** |
| Порт источника | **443** |
| HTTPS для источника | **Включён** |
| HTTP Host при обращении к источнику | **`vpn.example.com`** |
| TLS SNI при обращении к источнику | **`vpn.example.com`** |
| Собственный домен раздачи | **`cdn.example.com`** |
| Технический домен | Выдаёт Timeweb после создания ресурса; скопируйте точное значение |
| Сертификат на стороне CDN | Действующий сертификат для **`cdn.example.com`** |

Если адрес и порт заданы одним полем, используйте `vpn.example.com:443`.
Если это два отдельных поля — домен без порта и `443` в поле порта.
Полный URL вводите только в поле, которое явно требует URL.

1. В Timeweb Cloud откройте **Сети → CDN → Добавить**.
2. Источник — **Домен**, укажите `vpn.example.com`, порт **443**.
   Включите **HTTPS-соединение для источника**. Не указывайте `cdn.example.com` как источник.
3. Добавьте собственный домен раздачи **`cdn.example.com`**.
4. В DNS создайте **CNAME** для `cdn` на технический домен, показанный Timeweb.
   Копируйте точное значение из панели; не подставляйте IP VPS и не придумывайте технический домен.
   Удалите конфликтующие A/AAAA для этого же имени, если они были созданы ранее.
5. Дождитесь проверки домена и выпустите HTTPS-сертификат **для домена раздачи** в CDN.
   Это отдельный сертификат от сертификата источника, выданного установщиком.
6. В настройках обращения к источнику задайте **HTTP Host = `vpn.example.com`**.
   TLS SNI источника также должен быть `vpn.example.com` (обычно берётся из адреса источника).
   Не отключайте проверку сертификата источника. Если текущая панель не позволяет задать
   Host/SNI, уточните поддерживаемый способ у Timeweb: без них Nginx отклонит запрос.
7. Отключите **CDN-кэширование**, **кэширование в браузере**, **«Всегда онлайн»**.
   Не включайте игнорирование query-параметров: `session` и `part` должны доходить до источника.
   Для туннеля также не нужны оптимизация/сжатие/нарезка статического контента и редиректы пути.
8. Сохраните настройки и дождитесь применения конфигурации и DNS.

<a id="dns-cdn"></a>

### DNS после создания CDN: CNAME для `cdn`

В карточке CDN скопируйте **технический домен**, выданный именно вашему ресурсу.
Он отличается от вашего `cdn.example.com`. Далее обозначим его как
`YOUR_CDN_HOST_FROM_TIMEWEB` — это обозначение, а не значение для вставки в DNS.

В той же DNS-зоне, где создавали A для `vpn`, добавьте:

| Поле в DNS-панели | Значение |
|---|---|
| Тип записи | **CNAME** |
| Имя / поддомен / хост | **`cdn`** (или полное `cdn.example.com`, если так устроена панель) |
| Значение / цель / canonical name | **Технический домен из карточки CDN** |
| TTL | Можно оставить значение по умолчанию |

В цели CNAME не должно быть `https://`, `/`, `:443` и IP-адреса VPS.
Если панель DNS требует завершающую точку у полного имени, добавьте её.
Для `cdn` не должно оставаться конфликтующих A/AAAA или другого CNAME.
Проксирование сторонним DNS-провайдером здесь также не включайте.

**Итоговая схема DNS**:

```text
vpn.example.com.    A        203.0.113.10
cdn.example.com.    CNAME    YOUR_CDN_HOST_FROM_TIMEWEB.
```

Замените IP и техническое имя реальными значениями. Если Timeweb создал CNAME
автоматически, достаточно проверить существующую запись — дубликат не нужен.

Проверка на Windows:

```powershell
Resolve-DnsName cdn.example.com -Type CNAME
Resolve-DnsName cdn.example.com -Type A
```

Первый запрос должен показывать технический домен вашего CDN. Второй разрешает
его в IP узлов CDN. Адреса CDN могут различаться; их не нужно вручную копировать в A-запись.
После корректного DNS выпустите сертификат CDN и дождитесь статуса готовности.
Получаются два отдельных сертификата: `vpn.example.com` на VPS и `cdn.example.com` в CDN.

### Контроль настроек перед подключением

| Параметр | Требуемое состояние |
|---|---|
| HTTPS от клиента до CDN | Работает, сертификат соответствует `cdn.example.com` |
| HTTPS от CDN до VPS | Включён; сертификат источника соответствует `vpn.example.com` |
| CDN-кэширование | Выключено |
| Кэширование в браузере | Выключено |
| «Всегда онлайн» / выдача старого кэша | Выключено |
| Параметры URL `session`, `part` | Доходят до источника без удаления |
| Перенаправления и изменение пути туннеля | Не включены |

Названия разделов могут меняться. Ориентируйтесь на смысл параметров, а не на
«третий переключатель» из видео. Используется **GET/packet-up**, поскольку текущая
[документация Timeweb](https://timeweb.cloud/docs/cdn/settings/http-headers)
перечисляет GET, HEAD и OPTIONS. Наличие GET само по себе не гарантирует передачу тела:
это нужно подтвердить проверкой туннеля на вашем CDN-ресурсе.

Ссылки провайдера: [создание CDN](https://timeweb.cloud/docs/cdn/create),
[источник и домены](https://timeweb.cloud/docs/cdn/settings/origin-and-domains),
[кэширование](https://timeweb.cloud/docs/cdn/settings/cache).

<a id="connect"></a>

## 4. Проверить CDN и подключить Happ

На VPS, из папки скачанного проекта:

```bash
python3 probe.py --xray /usr/local/bin/xray \
  --settings /var/lib/vless-timeweb-cdn/settings.json \
  --credentials /var/lib/vless-timeweb-cdn/credentials.json
```

Без `--origin` проверка использует именно домен CDN, проверяет внешний IP и DNS-датаграммы
внутри туннеля. Для сравнения прямого источника повторите с `--origin`.
Если все ключи отозваны, проверка сообщит о пропуске: создайте активный ключ в панели.
Проверка с VPS не заменяет проверку из сети вашего мобильного оператора.

Откройте админку по **домену источника** и адресу, напечатанному установщиком.
Там можно создавать, отзывать и удалять ключи, копировать VLESS-ссылки, скачивать QR,
смотреть счётчики трафика и менять пароль панели. Каждая ссылка сразу использует домен CDN.
Для первого ключа также доступны:

```bash
cat /var/lib/vless-timeweb-cdn/client.txt
# QR: /var/lib/vless-timeweb-cdn/client-qr.png
```

Импортируйте ссылку или QR в актуальный Happ с поддержкой XHTTP и его расширенных
GET/packet-up параметров. Проверьте загрузку **и отправку** файлов, повторное подключение
после простоя и работу на нужной мобильной сети. Если клиент теряет `extra` при импорте,
обновите клиент или используйте совместимый Xray JSON. Базовый `client.json` — локальный
SOCKS-профиль Xray, не готовая настройка системного TUN.

HTTPS завершается на CDN: провайдер является посредником этого транспорта. Для панели
используйте только прямой адрес источника; сторонним «проверялкам ключей» рабочие VLESS-ссылки не передавайте.

<a id="panel"></a>

## Как пользоваться админкой

1. Откройте в браузере полный адрес, напечатанный установщиком. Он имеет вид
   `https://vpn.example.com/manage-<случайная-строка>/`. Сохраните его в закладках:
   на главной странице сайта ссылки на панель нет.
2. Введите логин и пароль, заданные при установке.
3. В блоке **«Новое подключение»** введите название устройства и нажмите **«Создать ключ»**.
   Удобно делать отдельный ключ для каждого устройства, чтобы отзывать доступ независимо.
4. Нажмите **«Копировать ссылку»** и импортируйте её в Happ. Для телефона можно
   отсканировать QR с экрана другого устройства или скачать QR-файл.
5. В Happ включите подключение и выполните проверки ниже.
6. Чтобы отозвать доступ, нажмите **«Деактивировать»**. **«Удалить»** убирает ключ
   из панели. Повторная выдача доступа возможна созданием нового ключа.

Изменения ключей перезапускают Xray: текущие клиенты могут кратковременно переподключиться.
Пароль админки меняется по ссылке **«Сменить пароль»**; SSH-пароль это не меняет.
Если нужно узнать сохранённый адрес панели, выполните на VPS:

```bash
python3 -c 'import json; s=json.load(open("/var/lib/vless-timeweb-cdn/settings.json")); print("https://"+s["domain"]+s["panel_path"]+"/")'
```

### Что проверить на устройстве

- Подключение включается, сайты открываются.
- Внешний IPv4 соответствует выходному IP VPS; обычно это тот же единственный IPv4.
- Работают и скачивание, и отправка файла: одна открывшаяся страница не проверяет upload.
- После выключения/включения подключения и простоя связь восстанавливается.
- Всё работает именно в нужной Wi-Fi/мобильной сети.
- При деактивации тестового ключа доступ у этого профиля прекращается.

Статистика панели относится к ключам и трафику Xray. Она не заменяет биллинг Timeweb:
расход трафика и лимиты оплаты проверяйте также в панели провайдера.

<a id="diagnostics"></a>

## Обновление и диагностика

Скачайте новый снимок, проверьте SHA256SUMS и запустите `bash start.sh --update`.
Обновление сохраняет UUID, XHTTP path, активные/отозванные ключи и логин/пароль панели.
При ошибке восстанавливаются сохранённые управляемые файлы; установленные пакеты,
сертификаты и данные для повторной попытки остаются. Резервные копии содержат секреты:
`/var/lib/vless-timeweb-cdn/backups/`.

```bash
systemctl status xray nginx vless-cdn-admin vless-cdn-panel
journalctl -u xray -u vless-cdn-admin -u vless-cdn-panel -n 100 --no-pager
nginx -t
```

### Как понять, на каком этапе ошибка

| Симптом | Что проверить первым |
|---|---|
| SSH не подключается | Состояние VPS, публичный IP, SSH-порт и firewall провайдера |
| `DNS A must contain only ...` | A-запись **`vpn`**, правильную DNS-зону и отсутствие лишних IP |
| Ошибка выпуска Let's Encrypt | DNS источника, доступность TCP 80 и отсутствие неверной AAAA |
| Сообщение об уже установленном Nginx/Xray | Нужен чистый VPS; не запускайте поверх другой панели |
| Админка отдаёт 404 | Полный сохранённый путь `/manage-.../`, а не только корень домена |
| Сайт источника открывается, но туннеля нет | Проверьте сначала `probe.py --origin`, затем обычный `probe.py` |
| Прямая проверка проходит, CDN-проверка нет | CNAME `cdn`, сертификат CDN, Host/SNI источника и кэширование |
| CDN возвращает 502/504 | Доступность VPS:443 для CDN, имя источника, его сертификат и работа Nginx/Xray |
| Скачивание есть, отправки нет | Поддержку GET body и сохранение расширенных XHTTP-параметров клиентом |
| Все ключи отозваны, проверка пропущена | Создайте активный ключ; пропуск проверки не означает успех туннеля |

Для проверки прямого источника используйте полную команду:

```bash
python3 probe.py --origin --xray /usr/local/bin/xray \
  --settings /var/lib/vless-timeweb-cdn/settings.json \
  --credentials /var/lib/vless-timeweb-cdn/credentials.json
```

Затем выполните ту же команду без `--origin` — это проверка через CDN.
Обычное открытие корня домена CDN в браузере не доказывает работоспособность VLESS.

- Источник работает, CDN нет: проверьте CNAME, оба сертификата, Host/SNI, отсутствие кэша
  и сохранение GET body/query. Не меняйте `packet-up` на `auto` только на одной стороне.
- Загрузка работает, отправка нет: проверьте сохранение тела GET и поддержку расширений в клиенте.
- Ошибка DNS до установки: A домена источника должен содержать только входной IP VPS.
- Туннель работает с VPS, но не у оператора: это отдельная сетевая проверка. Скрипт
  не гарантирует попадание адресов CDN в белые списки и работу во всех регионах.

## Проверки и происхождение

В CI: ShellCheck и Bash syntax, manifest, unit-тесты, реальный Xray, Nginx с двумя
TLS-hop для имитации CDN (GET-only edge), загрузка/отправка 4 MiB, UDP внутри туннеля,
отзыв ключей, счётчики, systemd и права Unix-сокетов, вход через Chromium.
Это не тест коммерческого ресурса Timeweb. Развёртывание на реальном VPS и проверка
через Timeweb выполняются отдельно после предоставления сервера и доменов.
